## 5) Findings, Decisions, Assumptions

- **Finding:** The existing `.git` state cannot resolve `HEAD`, and its configured remote targets an unrelated Fixed Income repository. This state is unsafe for staging or pushing Atlas.
- **Decision:** Preserve the existing `.git` directory untouched and create a clean publication staging repository after validation. This prevents accidental history repair, cross-project commits, or a push to the wrong remote.
- **Finding:** `gh` is installed. An invalid `GH_TOKEN` environment value currently masks a separate keychain credential for account `linroger`.
- **Decision:** GitHub commands will run with `GH_TOKEN` removed from their environment and authentication will be rechecked before any remote mutation. No token value will be printed or copied.
- **Finding:** The lockfile contained 289 `resolved` tarball URLs under the unreachable private host `npm.mirrors.msh.team`. The first `npm ci` exhausted retries against that host and ended with npm's internal `Exit handler never called` error.
- **Decision:** Normalize only the unreachable lockfile host to `registry.npmjs.org`, preserving package names, versions, integrity hashes, and dependency graph. This is a reproducibility repair rather than a dependency update.
- **Finding:** After a clean install, `npm run check` passes and the production bundle builds, but `npm run lint` fails with 27 errors, `npm test` fails because no test files exist, and `npm audit` reports 18 advisories (1 low, 7 moderate, 10 high). The build also emits a 572.22 kB frontend chunk and a 2.4 MB server bundle warning.
- **Finding:** The final dependency pass upgraded compatible transitive packages, moved React Router to 8.3.0 and `@hono/node-server` to 2.0.12, and updated browser compatibility data. `npm audit --omit=dev` now reports zero vulnerabilities. The remaining full-audit total is six moderate development-only paths: the Vite Hono adapter still pins node-server 1.x, and current Drizzle Kit retains an old esbuild compatibility loader. The site does not use these dependencies in the deployed static artifact.
- **Finding:** The current browser app is coupled to root-relative `/assets` and `/api/trpc`, uses `BrowserRouter` without a repository basename, and depends on Hono/MySQL/auth for several routes. The emitted bundle can be served by its Node process, but it is not a functional GitHub Pages artifact in its current form.
- **Finding:** OAuth `state` is a predictable base64-encoded callback URI and is not bound to the initiating browser, enabling login CSRF/session swapping. A dedicated hardening slice is in progress.
- **Finding:** Public journey detail responses expose storage `fileId` plus exact photo latitude, longitude, and timestamp, while published photos persist expiring signed URLs even though a re-signing route exists.
- **Finding:** The current detached job wrapper retries provider generation up to three times. An ambiguous network timeout can therefore create duplicate paid image/video jobs.
- **Finding:** The UI/router allow nine 7 MiB photos, which expand to about 84 MiB as base64 and exceed the 50 MiB Hono request limit. File rejection was silent and arbitrary `image/*` MIME values were accepted.
- **Finding:** Atlas has no direct MiniMax client. The existing `api/ai/gateway.ts` implements Kimi agent-gateway `/tools`, whose request and response contracts are incompatible with MiniMax's domestic image endpoint and asynchronous video lifecycle.
- **Decision:** The GitHub Pages artifact will be an explicit read-only demo with embedded public sample data and server-dependent controls disabled. No credential will be placed in a `VITE_` variable or static asset.
- **Decision:** MiniMax validation will use one `image-01` base64 response and one V1 `MiniMax-Hailuo-02` 512P/6-second image-to-video task, submitted exactly once and polled by task ID. Estimated ordinary pay-as-you-go cost is approximately CNY 0.625.
- **Finding:** The supplied MiniMax credential is valid on `https://api.minimaxi.com`. Both requested domestic generation modalities passed. Artifacts and resumable provider identifiers remain in a mode-0700 temporary directory outside the repository; logs contain only redacted identifiers and non-sensitive hashes/metadata.
- **Finding:** MiniMax's current `/v1/files/retrieve_content` route returned provider code 2013 (`invalid file purpose`) for the successful `video_generation` file. The documented metadata route `/v1/files/retrieve` returned a valid HTTPS `download_url`; downloading that URL produced the expected MP4.
- **Decision:** The smoke harness now retrieves video metadata, validates the HTTPS URL and `video_generation` purpose, downloads without logging the URL, validates the MP4 signature, and supports `MINIMAX_RESUME_FILE` so a completed/processing task can be polled and recovered with zero additional create requests.
- **Finding:** OAuth login state was predictable and browser-unbound. The completed hardening slice now starts authorization server-side, stores a signed ten-minute HttpOnly/SameSite transaction cookie, validates state with constant-time comparisons, consumes the cookie once, restricts return paths, and adds no-store/referrer protections.
- **Finding:** The deterministic itinerary fallback invented destination-specific names such as “Old Town” and then described them as real. It now cycles verified research places when available and explicitly labels generic activity anchors when no place names can be verified; two regression tests cover both branches.
- **Finding:** AI job polling mirrored query data through effects and could continue polling after provider-terminal failures. It now derives UI state directly from provider data, stops only for provider `done`/`failed` states, and keeps transient poll transport errors nonterminal so the browser cannot provoke a second paid create.
- **Finding:** The final Pages build uses a repository-aware Vite base, `HashRouter`, embedded public sample journeys, a fail-closed tRPC alias, and explicit notices for backend-only routes. The static entry fell from 572.22 kB to 272.34 kB, and no `/api/trpc` endpoint is present in emitted assets.
- **Finding:** Pre-release review found an unauthenticated storage-signing IDOR: arbitrary gateway IDs reached the signer, film inputs lacked ownership checks, and deleted-photo links could remain signable. New uploads now receive 24-hour HMAC capabilities bound to the authenticated user; film and publish mutations verify those capabilities; private previews require the session; and public re-signing first proves the file remains attached to an extant journey.
- **Finding:** The declared image MIME was previously trusted after Base64 decoding, and a first header-only repair still accepted truncated pseudo-images. JPEG, PNG, and WebP uploads now undergo a complete native pixel decode with strict warnings, matching format metadata, a 16,384-pixel edge ceiling, and a 64-megapixel input limit before the original bytes reach storage.
- **Finding:** Public journey list/detail rows exposed the stable internal `userId`; both routes now use an explicit allowlisted projection. Protected-route OAuth also lost pathname/query/hash; the login redirect now carries a safe `returnTo` through the signed transaction.
- **Finding:** Vitest's configuration silently excluded all frontend tests. Test discovery now includes both `api/**` and `src/**`, raising the actually executed suite from 21 tests in five files to 34 tests in eight files.
- **Finding:** The React inspection plugin injected `code-path` source-layout metadata into production DOM. It is now restricted to development `serve` mode; a repository-base static rebuild contains no `code-path`, backend endpoint, or credential pattern.
- **Finding:** The final re-review found three additional boundary inconsistencies: journey like/replicate actions bypassed the OAuth return-path helper, journey publication did not enforce the shared nine-photo limit or capability uniqueness, and the MiniMax repository guard derived its root from the caller's working directory. All three now use the shared redirect/limit contracts. The smoke harness derives its root from `import.meta.url` and canonicalizes existing ancestors, closing both caller-directory and macOS `/tmp` → `/private/tmp` alias bypasses; regression checks cover duplicate/over-limit publication and invocation through the alias from an unrelated directory.
