# Atlas Website

Atlas is a travel-storytelling web app that turns first-person journeys into shareable maps, stories, banners, narration, and short films. The repository contains both a React/Vite frontend and a Hono/tRPC/MySQL backend.

The public GitHub Pages deployment is intentionally a **read-only static demo**. It uses embedded sample journeys so Explore, journey detail, maps, navigation, and responsive layouts work without shipping credentials or pretending that GitHub Pages can run the backend. Account, upload, planning, and generation features require the full server deployment.

## Architecture

- `src/` — React 19 interface, routes, static-demo adapter, and UI components.
- `api/` — Hono server, tRPC routers, Kimi OAuth, provider gateway, EXIF analysis, and media proxying.
- `db/` — Drizzle/MySQL schema and query modules.
- `scripts/minimax-domestic-smoke.mjs` — cost-bounded MiniMax mainland API verification; it is not part of the browser bundle.
- `.github/workflows/deploy-pages.yml` — builds and deploys only the credential-free static demo.

## Local setup

Node.js 22 is the supported development/runtime baseline.

```bash
npm ci
cp .env.example .env
npm run dev
```

For a production full-stack build:

```bash
npm run build
NODE_ENV=production npm start
```

The backend needs MySQL, Kimi OAuth credentials, and (for live AI features) the server-only gateway variables documented in `.env.example`. Never prefix provider secrets with `VITE_`; Vite exposes those values to browsers.

## Quality gates

Run the reproducible project check:

```bash
./init.sh
```

It installs the exact lockfile when needed, then runs TypeScript checks, ESLint, Vitest, and the production build. The individual commands are:

```bash
npm run check
npm run lint
npm test
npm run build
```

Build the same static artifact used by GitHub Pages:

```bash
VITE_STATIC_DEMO=true \
VITE_BASE_PATH=/Atlas-Website/ \
npx --no-install vite build
```

## MiniMax mainland API smoke test

The smoke test calls `https://api.minimaxi.com` with one `image-01` request and one `MiniMax-Hailuo-02` 512P, six-second image-to-video request. At the price observed during the August 2026 verification, the pair was approximately CNY 0.625; check current MiniMax pricing before running it again.

Enter the key without terminal echo and keep it out of `.env`, shell history, logs, and source:

```bash
unset MINIMAX_API_KEY
read -rs 'MINIMAX_API_KEY?MiniMax API key: '
printf '\n'
export MINIMAX_API_KEY
npm run test:minimax
unset MINIMAX_API_KEY
```

The runner:

- submits each paid create request at most once;
- stores generated bytes and a resumable task record in a private temporary directory outside the repository;
- redacts provider IDs and never prints the key, Base64 payload, or signed download URL;
- polls with a 15-minute bound and validates image/MP4 signatures; and
- enables MiniMax's AI-generated-content watermark.

If generation succeeds but retrieval is interrupted, resume the same task with zero additional create requests:

```bash
MINIMAX_RESUME_FILE=/private/path/to/task.json npm run test:minimax
```

Official contracts: [image generation](https://platform.minimaxi.com/docs/api-reference/image-generation-t2i), [V1 image-to-video](https://platform.minimaxi.com/docs/api-reference/video-generation-i2v), [video task query](https://platform.minimaxi.com/docs/api-reference/video-generation-query), and [file metadata/download](https://platform.minimaxi.com/docs/api-reference/file-management-retrieve).

## Security and deployment notes

- OAuth authorization starts on the server and uses a signed, one-time, ten-minute transaction cookie. Configure `OAUTH_CALLBACK_URL` when the public callback is not safely derivable from the request origin.
- Public journey DTOs omit storage IDs and precise photo EXIF coordinates/timestamps. Published photos use stable same-origin media paths instead of persisting expiring signed URLs.
- Paid provider create calls are single-shot to prevent duplicate charges after ambiguous timeouts. The current in-process job runner is not restart-durable; production scaling should persist provider task state in a queue/database before adding automatic recovery.
- Photo creation currently uses bounded Base64 JSON uploads. A high-volume deployment should move to direct, resumable object-storage uploads and strip unnecessary EXIF from public derivatives.
- `npm audit --omit=dev` is expected to be clean. Remaining full-audit findings are confined to development-only transitive tooling and are tracked as maintenance work rather than fixed with unsafe dependency downgrades.
